# Настройка Git-агента для работы с Bitbucket

## Краткое руководство

Теперь ваш ИИ-агент может выполнять Git-команды в репозиториях Bitbucket с автоматической аутентификацией.

## Что было сделано

1. **Добавлена поддержка аутентификации** в `local_git_tool.py`:
   - Агент автоматически добавляет учётные данные к HTTPS URL
   - Поддерживается вход по логину/паролю или токену
   - SSH URL остаются без изменений

2. **Создан файл `.env`** с настройками:
   ```
   BITBUCKET_USERNAME=admin
   BITBUCKET_PASSWORD=123321
   ```

## Как использовать

### 1. Отправьте агенту ссылку на репозиторий

Примеры команд, которые можно отправить агенту:

```
Клонируй репозиторий https://bitbucket.sberbank.ru/scm/PROJECT/my-repo.git
```

```
Сделай коммит с сообщением "Update version" в ветку release-1.0
```

```
Сделай push изменений в удалённый репозиторий
```

### 2. Агент автоматически выполнит аутентификацию

При клонировании HTTPS URL агент преобразует его в формат:
```
https://admin:123321@bitbucket.sberbank.ru/scm/PROJECT/my-repo.git
```

Это позволяет выполнять операции без дополнительных запросов пароля.

## Рекомендуемая настройка безопасности

**Важно**: Вместо пароля рекомендуется использовать HTTP Access Token:

1. Откройте https://bitbucket.sberbank.ru
2. Перейдите в настройки профиля (Manage account)
3. Выберите "App passwords" или "HTTP access tokens"
4. Создайте новый токен с правами:
   - Read (чтение репозиториев)
   - Write (запись/коммиты)
5. Скопируйте токен и замените им пароль в файле `.env`:
   ```
   BITBUCKET_USERNAME=ваш_логин
   BITBUCKET_PASSWORD=ваш_токен
   ```

## Примеры сценариев использования

### Сценарий 1: Установка релиза
```
1. Клонируй репозиторий https://bitbucket.sberbank.ru/scm/PROJ/app.git
2. Переключись на тег v1.2.3
3. Создай ветку release-1.2.3
4. Обнови файл version.txt с версией 1.2.3
5. Сделай коммит "Release version 1.2.3"
6. Сделай push в удалённый репозиторий
```

### Сценарий 2: Хотфикс
```
1. Клонируй репозиторий
2. Создай ветку hotfix-issue-123 от master
3. Исправь файл config.py (измени параметр X на Y)
4. Сделай коммит "Fix issue #123"
5. Сделай push и создай pull request
```

## Переменные окружения

| Переменная | Описание | Пример |
|------------|----------|--------|
| `BITBUCKET_USERNAME` | Логин пользователя | `admin` или `user@company.com` |
| `BITBUCKET_PASSWORD` | Пароль или токен доступа | `123321` или `ATBBxxx...` |
| `GIT_WORK_DIR` | Рабочая директория для операций | `/tmp/sandbox` |

## Поддерживаемые Git-команды

Агент может выполнять следующие команды через естественный язык:

- `clone` — клонирование репозитория
- `checkout` — переключение веток/тегов
- `branch` — создание/удаление веток
- `add` — добавление файлов в staging
- `commit` — создание коммитов
- `push` — отправка изменений в Bitbucket
- `pull` — получение изменений из Bitbucket
- `merge` — слияние веток
- `diff` — просмотр различий
- `status` — статус репозитория
- `log` — история коммитов
- `fetch` — загрузка данных из удалённого репозитория

## Troubleshooting

### Ошибка аутентификации
Если получаете ошибку authentication failed:
1. Проверьте правильность логина и пароля/токена
2. Убедитесь, что у пользователя есть права на репозиторий
3. Для токена проверьте срок действия и права доступа

### Ошибка SSL сертификата
Для внутренних серверов может потребоваться отключить проверку SSL:
```bash
git config --global http.sslVerify false
```

Или укажите путь к корневому сертификату в `.env`:
```
GIT_SSL_CA_BUNDLE=/path/to/ca-bundle.crt
```

## Безопасность

⚠️ **Важные замечания**:

1. Файл `.env` содержит чувствительные данные — не коммитьте его в Git
2. Используйте токены вместо паролей где это возможно
3. Ограничьте права токена только необходимыми операциями
4. Регулярно обновляйте токены доступа
