# Troubleshooting

## SSLError / CERTIFICATE_VERIFY_FAILED при чтении Confluence

### Причина

У сервера Confluence самоподписанный сертификат, а его корневой сертификат
не установлен в системное хранилище машины. Агент проверяет сертификат
сервера по умолчанию и обрывает соединение, если не может его подтвердить.

### Решение — правильное

Получить корневой сертификат внутреннего удостоверяющего центра в формате PEM
и указать путь к нему:

```bash
CONFLUENCE_CA_BUNDLE=/path/to/internal-ca.pem
```

Проверка при этом продолжает работать, просто доверие идёт к внутреннему
центру, а не к публичным.

### Решение — временное

```bash
CONFLUENCE_VERIFY_SSL=false
```

Проверка выключается целиком. Это значит, что программа соединяется с тем,
кто ответил по адресу, и не проверяет, он ли это. Последствия два: токен
Confluence уходит в каждом запросе тому, кто перехватит соединение, и — что
важнее для агента — из Confluence приходит план установки, то есть намерение.
Подменённая страница станет для агента законным основанием для изменения
конфигов; человеческие подтверждения это ловят, но план придёт уже
правдоподобным.

Команда `check-config` отдельной строкой показывает, что проверка выключена.
Оставлять так на постоянной основе не следует.


## Connection reset by peer

### Причина

Корпоративная сеть перенаправляет запрос на промежуточный шлюз, который разрывает TLS-соединение.

### Проверка

```bash
curl -v <адрес сервиса аутентификации>
```

### Решение

Установить `VERIFY_SSL=false` в `.env` или использовать внутренний URL аутентификации.

## 401 Unauthorized

### Причина

Не указан Authorization Key (токен) или невалидный credentials.

### Решение

Проверить переменные:
- `GIGACHAT_CREDENTIALS` — токен должен быть валидным
- `GIGACHAT_AUTH_URL` — правильный URL для получения токена

---

## 402 Payment Required

### Причина

У проекта отсутствует активный пакет или квота GigaChat API.

### Решение

Проверить квоты в личном кабинете GigaChat.

---

## mTLS: FileNotFoundError для сертификата

### Причина

Файл сертификата или ключа не найден по указанному пути.

### Решение

Проверить абсолютные пути в переменных:
- `GIGACHAT_CERT_FILE`
- `GIGACHAT_KEY_FILE`

---

## Ошибка: не задан режим аутентификации

### Причина

Не заданы ни mTLS-параметры, ни токен.

### Решение

Указать хотя бы один режим в `.env`:
```bash
# mTLS
GIGACHAT_CERT_FILE=/path/to/cert.pem
GIGACHAT_KEY_FILE=/path/to/key.pem

# ИЛИ токен
GIGACHAT_CREDENTIALS=your_token_here
```
