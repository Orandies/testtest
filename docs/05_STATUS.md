## 6. Что сделать у себя

### Обязательно: сертификат Confluence

Раньше агент соединялся с Confluence, не проверяя сертификат сервера, — значение
было зашито в код. Теперь проверка включена. **Чтение Confluence упадёт с ошибкой
`CERTIFICATE_VERIFY_FAILED`, пока не сделаете одно из двух:**

```
# Правильно: указать корневой сертификат внутреннего центра
CONFLUENCE_CA_BUNDLE=/путь/до/internal-ca.pem

# Временно, пока сертификата нет
CONFLUENCE_VERIFY_SSL=false
```

Обе переменные — в `.env`, описаны в `.env.example`. Разбор ошибки —
в [Troubleshooting.md](Troubleshooting.md).

Почему поменяли: из Confluence приходит план установки, то есть намерение — одно
из двух оснований, на которых агент строит изменения конфигов. Без проверки
сертификата подменённая страница станет для агента законным входом, а токен
Confluence уходит в каждом запросе тому, кто перехватит соединение.

### Проверить, что всё поднялось

Установка: `python -m venv .venv`, активировать, затем `pip install -e ".[dev]"`.

|---|---|
| `pytest` | 95 passed |
| `ruff check .` | All checks passed |
| `lint-imports` | Contracts: 4 kept, 0 broken |
| `release-promotion-agent demo` | Сценарий целиком, в конце цепочка аудита. Сеть не нужна |
| `release-promotion-agent check-config` | Что настроено и чего не хватает релизному сценарию |

### Что учесть при работе

- Зависимости — только из `pyproject.toml`. Разработка `pip install -e ".[dev]"`,
  образ `pip install .`.
- `pre-commit install` включает проверки на коммите. После этого `git commit`
  требует, чтобы каталог `Scripts` виртуального окружения был в PATH, иначе
  `lint-imports` не найдётся и коммит отвалится.
- Каталога `app/` нет: запуск через `release-promotion-agent`.
- Разбор diff живёт в `analyzers/branch_diff.py`, не в `tools`.
- Состояние сессии в памяти процесса: перезапуск — сессия заново.

| Правило | Чем закреплено |
